# VDJ Companion 0.4.1

Fixes a cause of **Download error (502)** when loading a YouTube track into VirtualDJ.

Some YouTube audio links only become usable after a short waiting period. Companion now waits until the link is ready instead of requesting it too early and repeatedly replacing it. The wait remains covered by the existing request timeout, and later range requests reuse the ready link without waiting again. Upstream failures and timeouts are now logged for troubleshooting.

This addresses the availability-delay failure; other network or YouTube errors can still occur.

## Install or update

Existing users: close VirtualDJ and click **Install update & restart** in Companion. Settings, setlists and saved media are preserved.

New users: extract `vdj-companion-0.4.1-windows-x64.zip` to a permanent folder and run `START.bat`.

macOS users: use the separate **0.4.1 beta 1** release.

## Validation

162 automated tests, including long availability waits, repeated range requests, refreshed URLs, timeouts and cancellation. Live HTTP streaming was checked with all three search sources and yt-dlp 2026.10.26 and 2026.11.23; a complete audio track decoded successfully. The live samples did not require an availability delay, so delayed availability was verified with controlled tests. A new manual VirtualDJ deck test was not performed for this patch. Publication also requires the native build and extracted-package checks to pass.

Thanks to [@kernel-machine](https://github.com/kernel-machine) for reporting the cause and contributing the initial fix in [#13](https://github.com/rcsy-px/vdj-stream/pull/13).
